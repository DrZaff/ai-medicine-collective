# Integrating with NextSet later

## What was found

`DrZaff/nextset-strength` (commit `2f8651d`, read-only in this session) is an
**Expo / React Native** app (`App.js`, `src/*.mjs`, Expo SDK 58), not a
SwiftUI project, so there was no Swift target to add the watch features to.
This is therefore a standalone SwiftUI app, built so NextSet can adopt it
without changing the watch or the protocol.

## Shared data shapes

Field names follow NextSet's own objects.

| NextSet (`src/core.mjs`, `src/workouts.mjs`, `App.js`) | NextSet Sync |
|---|---|
| prescribed exercise `{id, name, sets, reps, rir, rest, tempo, kind, cue}` | `WorkoutExercise` (same names, plus `load`, `increment`) |
| prescription `{name, week, exercises}` / plan `{sessions:[…], profile:{units}}` | `Workout`; both import directly (`WorkoutImporter`) |
| log row `{sessionId, workout, exercise, exerciseId, exerciseIndex, set, load, units, reps, rir, pain, tempo, rest, duration_seconds, note, date}` | `SetRecord` (`sessionId`, `workoutName`, `exerciseName`, `exerciseId`, `exerciseIndex`, `setNumber`, `load`, `units`, `reps`, `rir`, `loggedAt`) plus `id`, `rev`, `ackState` |
| `csv()` columns `date … note` | `SetCSV`: the same 13 columns in the same order, then sync columns |

The tests import a plan and a prescription generated by NextSet's own
`generatePlan()` and `prescription()` (`protocol/fixtures/nextset-*.json`).

Not carried by the watch: `pain`, `tempo`, `note`, `duration_seconds`
(timed sets). They are empty in the CSV. Adding them would mean a new field on
the watch's set screen and a protocol field; the protocol ignores unknown
fields, so this can be added without breaking either side.

## Three ways to integrate

1. **Files (works today).** NextSet exports a prescription or plan as JSON →
   *Workouts → + → Import from Files* here. Sets come back as CSV in
   NextSet's column order (*History → Export CSV*).
2. **Swift package inside NextSet's iOS build.** `NextSetSyncCore` has no UI
   or Apple-only dependencies. An Expo native module (Expo Modules API, in
   Swift) can depend on it, plus `bluetooth.swift` from this
   app, and expose:
   * `sendWorkout(prescriptionJSON)` → `WorkoutImporter.importFile` + `SyncEngine.sendWorkout`
   * `syncNow()` → `SyncEngine.syncAll()`, then return `LocalStore.sets` as
     NextSet log rows (`sessionId`, `exerciseId`, `set`, `load`, `units`,
     `reps`, `rir`, `date`)
   * `status()` → `LinkState` (paired, last sync, pending counts)

   NextSet's bundle id is `com.zaffuto.nextsetstrength`. Its iOS target would
   need `NSBluetoothAlwaysUsageDescription`, `UIBackgroundModes:
   bluetooth-central`, added through an Expo
   config plugin.
3. **Merge the apps.** Point NextSet's logs at `LocalStore`, or copy records
   across using `SetRecord.id`, which is stable and unique, so repeated
   copies cannot duplicate.

Whichever you choose, the watch app and protocol v1 stay as they are, and one
watch can be paired with up to three phones or apps.

## The Swift interface

```swift
let store = try LocalStore(directory: folder)              // atomic JSON files
let engine = SyncEngine(store: store, link: someWatchLink, phoneName: "iPhone")
try await engine.pair(code: "1234")                        // person confirms on the watch
try await engine.sendWorkout(workout)                      // returns after the watch saved it
let report = try await engine.syncAll()                    // sets, sessions, Sleep Log, status
let nights = SleepAnalyzer.nights(store.sleepEntries, dataEndT10: store.sleepDataEndT10,
                                  zones: ZoneHistory(store.zones))
let csv = SetCSV.make(store.sets)
```

`WatchLink` is the only Bluetooth seam: `BLEWatchLink` (Core Bluetooth),
`SimulatedWatch` (demo mode and tests), and the test bridge to the real watch
code all implement it.
